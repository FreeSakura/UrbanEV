# 点预测输出契约：先核对泛函，再比较RMSE

核查日期2026-09-09。不能仅凭接口名称`mean`或`point`认定输出是预测均值。

## 源码核查

- Chronos-2：官方源码`predict_quantiles`的第二个返回值虽然名为`mean`，实际取训练分位水平0.5。固定源码版本为`4dbf163c2734c089cdf7da2b86fde48862ff9c6f`，见[源码](https://github.com/amazon-science/chronos-forecasting/blob/4dbf163c2734c089cdf7da2b86fde48862ff9c6f/src/chronos/chronos2/pipeline.py#L749)。因此，不能以改用该返回值来声称已经修复“中位数用于RMSE”的问题。
- TimesFM-3：官方仓库示例把`forecast`明确标为median forecast。固定源码版本为`8cb7eda91c2b416b37e99a979afc50f2a18e1791`，见[官方说明](https://github.com/google-research/timesfm/blob/8cb7eda91c2b416b37e99a979afc50f2a18e1791/README.md)。应核对实际后端与版本后记录输出含义，不能把通用宣传中的point forecast自动解释成条件均值。

这些是输出语义事实，不证明哪个模型会输赢。用中位数计算RMSE本身是合法评价，但不是该模型潜在均值预测能力的充分检验；旧Chronos-2筛查结论保持原协议状态。

## 固定比较规则

主榜对每个具名系统使用一个固定点输出，同时报告RMSE和MAE。原生中位数系统、分位数积分近似系统、训练期MSE适配系统分成不同具名条目，所有条目预先登记；不根据测试结果切换点输出。裁剪版和原始版分别报告，主口径固定为[0,1]裁剪。

新适配路线只使用训练区内的冻结基础模型预测与真实训练标签；验证区选择强度后冻结，测试区不能参与头部训练。稀疏分位数不足以无假设恢复真实条件均值，积分近似与训练适配都需明确名称和假设。

## 可检验的新方向

对有界占用率，有限分位数蕴含一组相容预测分布。先研究这组分布的均值界及其稳健中点，再用一个受约束的小型MSE头学习如何组合分位数。这是任务泛函适配假说，尚未证明新颖性、真实校准性或SOTA收益。它比“接口换成mean就得到均值”的做法有明确可验证对象。
