# 六折实验的Windows检查点写入恢复

## 故障与影响

Luna读取运行日志后定位到首个实际异常：fold4/H3、DLINEAR_O、seed20260922、固定学习率配置0.001，在提交epoch19检查点元数据时，`os.replace`返回`PermissionError [WinError 5]`。这是文件提交故障，不是模型损失发散或“未达到SOTA”的失败。

旧私有调度器每30秒读取最新的可变`*_resume.json`显示进度。Windows上未允许delete sharing的打开句柄会阻止删除或重命名操作；独立CPU文件实验复现了读句柄阻塞同路径替换。该竞争路径足以解释故障，但保留日志无法事后唯一确认当时的锁持有者。[Microsoft文件共享说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)

## 已执行的修复

- 私有调度器改为解析只追加的`train.log`事件，不再读取正在原子替换的检查点元数据。
- 确认原执行器退出后，按同一配置、目录与claim恢复；失败临时文件、旧日志与旧调度器均保留。
- 调度器代码变更通过受控重启生效，恢复的是训练→监督预测→两个基础模型→评分的完整流程，不是单独启动一条训练命令。
- 原子提交未成功的epoch19临时元数据虽与其检查点匹配，恢复仍采用最后提交的epoch18边界。已完成任务依完成回执跳过，没有更换种子或挑选更好结果。
- 冻结训练、预测、评分源码及配置均未修改，配置SHA仍为`c235ebddd0cbabb401b5e0f61e7fe5618560a5252911059e00b4cb2c56184494`。

Luna已确认出错任务恢复完成、后续任务继续，并核对了单一执行器／训练进程。后续进度与故障仍由Luna负责，Astra不恢复训练轮询。

## 验证与恢复成本

[两项文件回归测试](../../../tests/test_windows_checkpoint_observer.py)在Windows本地通过：持有检查点读句柄时替换失败，关闭后成功；持有独立日志读句柄时，检查点替换成功。它们不构造模型、不读取训练数据，也不以长时间“未再报错”替代竞争路径验证。

成本记账必须区分“重启后执行”和“重复执行”。原恢复记录曾将2992次更新、约488.7秒全部记作额外开销，这一归类已撤回：

| 项目 | 正确含义 |
|---|---|
| DLINEAR原epoch19 | 已计算但未提交；从18恢复后重复136次更新 |
| DLINEAR恢复后的epoch20 | 原注册任务必要的136次更新，不是额外重复 |
| 后续仅运行一次的PATCHTST任务 | 其2720次更新仍属原注册轨迹，不是额外重复 |
| 受控重启可能丢弃的未提交部分 | 尚未精确分离，保留未知项 |
| 已丢弃计算的耗时 | 不以恢复段或后续完整任务耗时冒充额外耗时；不能精确归属时记为未知 |

`1011960`描述全部完成任务的注册更新轨迹，不能再将其不加限定地称为此次实际物理更新总数。已确认的实际额外计算至少为136次更新；完整成本解释需同时保留恢复记录及未能精确分离的部分。

本次处理修复了可复现的观察／写入竞争路径，并恢复原实验；不代表完整六折已经完成，不改变其测试开分条件，也不新增定时任务或使用额度重置卡。
