# 两条信息线索的固定复核方案

> 阶段记录：下文保留原研究时点的结论和执行范围；当前公开状态见[项目状态](../PROJECT_STATUS.md)。目录迁移不改变原结果。

2026-09-10。协议见[配置](../../configs/research/SIGNAL_REPLICATION_V1.json)。本轮不恢复已失败的交换或观测算子。

主问题：训练段原始相关分组是否在下一开发窗口仍优于冻结Chronos-2全区域与随机分组？支持问题：滞后时长的收益能否跨越线性ridge与冻结Chronos-2，并超过同信息重复通道对照？新增通道数量和模型优化差异是要排除的替代解释。

第二折训练为[0,1171)，验证为[1171,1318)，测试为[1318,1464)。前折末段进入后折训练符合扩展窗口协议，不能继续宣称所有历史测试时间都未读取。这里只用第二折训练/验证前缀；历史审计曾研究全数据集，故新窗口也不宣称全局盲测。H3/H12、全部275区域、逐小时完整预测。

区域路线只保留最后288训练小时的绝对相关分组K32，与全区域、三个固定种子随机分组比较。观测路线固定同一相关分组，将每组占用序列与滞后一小时的时长序列配对；对照包括不增加信息的重复占用通道、固定跨区域时长错配。输入时间截止与变元顺序写入代码测试。时长不作为未来已知变量，不推断主动充电状态真值。

固定ridge沿用lambda0.01与最后占用值残差锚点，训练步长3；不根据本窗口修改超参数。复制占用特征会改变ridge的有效正则强度，因此该对照也检验简单重复特征是否足以解释提升。冻结模型不训练；只比较已冻结的构造。

推进需宏RMSE至少改善1%、MAE不变差、任一H的RMSE恶化不超过1%。区域与时长的参考、错配否定对照和双骨干联合要求见协议。区间估计采用按预测原点成块的配对重采样，保留区域及步长相关性；单窗口的区间不能代表城市或季节泛化。

运行顺序：数据数值与身份检查→冻结实现并运行单元测试→ridge与Chronos实验→独立完整性核查→如实公布通过、失败和不确定性。单GPU预计约10–20分钟，CPU ridge并行使用2线程；超时/内存不足记实现阻塞，不改组大小来凑结果。

源语义：官方[GitHub](https://github.com/IntelligentSystemsLab/UrbanEV)区分不可用/忙碌的占用和实际供电利用；[Dryad说明](https://datadryad.org/dataset/doi:10.5061/dryad.np5hqc04z)给出时长为区间累计小时。二者未提供足以验证本地小时标签端点及上线延迟的依据；离线收益不等于可部署物理模型。官方文档将occupancy称为百分比，但本项目冻结的历史GitHub快照曾按计数核验，不能对任意新下载百分比数据重复除以容量。
