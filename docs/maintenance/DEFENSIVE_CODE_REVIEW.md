# 开发阻碍与重复检查审阅

审阅日期：2026-09-15。范围包括通用训练入口、数据和评分边界、作者模型适配、冻结六折执行、工件检查以及 CI。重点是移除阻碍正常迭代的默认流程，不改写已有实验结论。

| 原行为 | 处理后的行为 | 验证 |
|---|---|---|
| 修改任意预测包 Python 文件后，通用 CLI 拒绝评价旧 checkpoint | 允许用当前兼容代码评价；结果记录训练/评价代码哈希及是否匹配 | 实际合成训练后以不同代码身份评价成功 |
| 每次运行反复扫描源码计算相同指纹 | 每次 CLI 调用计算一次，复用于 checkpoint 和报告 | 入口调用链核对 |
| 输出目录存在就退出，即使只是空目录或笔记 | 允许使用已有目录，只拒绝覆盖 `result.json` 和将写入的 `checkpoint.pt` | 已有笔记保留、空目录评价成功、原结果不覆盖 |
| 每个分支 push 和 PR 各跑一套 CI | 分支使用 PR CI，主分支保留发布后 CI；同 PR 新提交取消旧运行 | workflow 事件及并发配置 |
| 文档改动也安装 PyTorch、执行训练和构建全部论文 | 按改动范围选择：文档只运行资料检查，预测代码运行测试，论文源码才构建 TeX | 大小类路径选择回归测试 |
| 两个 CI job 重复执行大量相同测试 | 单个测试任务运行一次完整适用套件 | 删除重复预测测试任务 |
| PDF 页数、字体检查由 shell 和 Python 各执行一次 | 统一使用现有论文清单验证器 | 原页数、字体、文本与署名约束仍在清单中 |
| 日常贡献要求完整历史审计和反复全量验证 | 本地迭代用相关测试；资料检查和最终 CI 完成剩余验证 | 贡献指南及 AGENTS.md |

## 保留的必要检查

数据列、时间原点、训练前缀及目标单位不一致会直接改变科学结果；非有限值、形状错误和模型参数不兼容也应明确失败。它们保留在输入、评分及模型加载边界。输出保护只针对会被当前命令覆盖的结果文件。

通用 CLI 的代码变化不再要求额外许可或新建协议。该评价使用当前代码，报告通过 `evaluation_code_matches_training` 和两个代码哈希区分身份；不会把新执行冒充旧源码逐字复现。

旧六折 runner 的 20 epoch、固定种子、清单及执行身份属于该次已注册实验，不是所有研究的通用开发规则。本次没有修改其冻结配置或执行依赖，也没有重置已完成任务。历史报告中的人工审核措辞不应成为新任务内反复停工的依据。

## 验证与收益范围

新增测试实际覆盖“训练后修改代码身份仍可评价”“训练数据变更仍被识别”“已有笔记不阻塞输出”“已有结果不被覆盖”，以及文档、模型、论文和依赖改动的 CI 范围。

收益是减少无关阻塞、重复流程及不必要的日志/上下文读取；没有宣称训练数学运算本身加速，也没有测量 token 节省百分比。后续开发直接按[贡献指南](../../CONTRIBUTING.md)选择最小相关验证。
